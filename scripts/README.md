# scripts

Bootstrap, smoke, and developer automation scripts live here.

Operational helper entrypoints:

- `npm run capture:authorized-video`: isolated operator-approved capture helper for login-gated video PPT fallback. Default `--self-test` and `--dry-run` do not open a browser or run FFmpeg. Self-test verifies authorization negative gates and writes a redacted `sharedReceipt` for validation logs. Live capture requires `--run-capture --ack-authorized --approval-id ... --approved-by ... --url ...`; it uses a temporary browser profile, bounded FFmpeg recording, no audio by default, and prints a follow-up handoff command instead of uploading automatically.

Current smoke entrypoints:

- `run-assistant-run-worker-smoke.sh`: non-destructive Linux/deployment-target smoke for the AssistantRun background completion worker queue, workflow registration, and redacted video completion dispatch contract.
- `run-assistant-chat-contract-smoke.sh`: non-destructive local/deployment-target smoke for the user-facing chat contract: ordinary chat stays unrestricted and V3-aware, ReAct fallbacks stay natural-language only, and external callback payloads do not expose internal observability fields.
- `run-newbai-assistant-answer-smoke.sh`: local/deployment-target smoke for NewBai answer-quality handoff. It validates deterministic provider-input supply, the NewBai retrieval-ranking regressions, and, when `PLATFORM_DATABASE_URL` points at a disposable fixture database, the Postgres-backed AssistantRun route. It does not call a real LLM provider or enable `RETRIEVAL_SEARCH_BACKEND=postgres_lexical`.
- `run-newbai-customer-answer-smoke.sh`: deterministic offline smoke for NewBai customer-facing answer quality. It checks final-answer patterns, evidence-use intent, internal-field leakage, false report/page claims, existing-template reuse, ordinary-question routing, and template/report side effects. It does not call DataMax, a model provider, PostgreSQL, or static-page/report rendering; captured provider/live outputs can be supplied later through `NEWBAI_CUSTOMER_ANSWER_RESULTS_JSONL`.
- `run-static-page-quality-smoke.sh`: non-destructive local/deployment-target smoke for static-page data quality: evidence field candidates, media candidates, section-title hints, preview data gates, and Codex plan-only quality gates.
- `run-static-page-render-smoke.sh`: non-destructive local/deployment-target smoke that generates a representative static-page artifact and validates the final HTML, DOM/SVG chart fallback, safe ECharts JSON hydration island, manifest, written handoff files, standalone export-artifact validator, and export package contract.
- `run-static-page-browser-smoke.sh`: non-destructive local/deployment-target smoke that opens the generated static-page `index.html` in Chrome desktop/mobile viewports, captures screenshots, and checks visible modules, SVG/ECharts presentation, horizontal overflow, module overlap, text overflow, mobile module order, and delivery-ready manifest state.
- `npm run smoke:static-page-5way`: external-channel static-page/report concurrency smoke for five parallel artifact requests. Use `-- --self-test` to validate deterministic payload, status-url, artifact-link, and terminal-failure parsing fixtures without calling DataMax or requiring a bearer.
- `npm run smoke:cloudflare-fallback-2way`: read-only guard smoke for Codex host fallback concurrency and watched workflow queues. Use `-- --self-test` to validate deterministic model-gateway/queue-stat fixtures without calling DataMax or requiring operator credentials.
- `npm run smoke:main-chat-20way`: main-site chat concurrency smoke for parallel dataset chat-session creation and optional assistant-message polling. Use `-- --self-test` to validate deterministic payload, summary, percentile, and poll-result fixtures without calling DataMax or requiring a dataset id, cookie, bearer, or secret binding. Self-test is not a substitute for the live 20-way production gate.
- `npm run smoke:external-channel-20way`: third-party external-channel concurrency smoke for parallel SSE event calls and completed/answered accounting. Use `-- --self-test` to validate deterministic payload, SSE parser, summary, and percentile fixtures without calling DataMax or requiring a bearer. Self-test is not a substitute for the live 20-way production gate.
- `npm run smoke:p2-summary-only-dry-run`: non-destructive P2 parsing/fact-store wrapper for `document-fingerprint-backfill`, `fact-index-backfill`, and `document-enrichment-backfill`. It always passes `--dry-run --summary-only --pretty`, has no `--confirm-real-run` path, writes sanitized stdout/stderr receipts, and can load a deployment env file without printing values. Use `-- --self-test` to validate command construction, summary parsing after database notice lines, and redaction without calling DataMax or requiring binaries.
- `run-customer-web-codex-executor-smoke.sh` / `npm run smoke:customer-web-codex-executor`: non-destructive local/deployment-target smoke for Customer Web Codex executor routing, host-agent safety, right-side shelf normalizers, artifact projection, product-change blocking, readiness self-test, and build readiness. The receipt includes `acceptance_status` to separate passed no-live evidence from pending controlled-live gates, with live-readiness fields, a machine-readable controlled-live input checklist, an approval request summary, and the redacted command-template contract read back from the per-run live-smoke self-test child report. Set `CUSTOMER_WEB_CODEX_SMOKE_INCLUDE_VIDEO_PPT_ROLLUP=true` to include the consolidated no-live video/PPT regression gate before release approval.
- `run-customer-web-codex-readiness.sh` / `npm run smoke:customer-web-codex-readiness`: read-only deployment-target check for Customer Web Codex env/profile readiness. It parses the env file without sourcing it, treats a readable env file as authoritative over conflicting shell env, verifies Right Code named-key usage, capability allowlists, host kind, real-exec flag, and task workspace root boundaries, and never prints provider key values. Use `--json-stdout` with `CUSTOMER_WEB_CODEX_REPO_ROOT=/srv/aiv3/repo` for SSH/stdin checks that return redacted JSON without writing report files on the deployment host. Not-ready reports include `missing_task_allowlist_capabilities`, `missing_profile_allowed_capabilities`, and non-secret `remediation.required_env_updates` for the operator-approved env/profile patch.
- `npm run smoke:production-placeholder-readiness`: read-only local/deployment-target check for production placeholder runtime risk. It parses one or more env files without sourcing them and never prints provider key values or raw env values. It verifies that `DATASET_OUTPUT_RUNTIME_MODE`, `DATASET_OUTPUT_RUNTIME_PROVIDER`, and `DATASET_OUTPUT_RUNTIME_MODEL` are explicitly configured and not using placeholder defaults, and inspects `report-planner-worker` source for the deterministic business-template AST planner; `--allow-not-ready` records missing/placeholder keys without failing the command, and `--self-test` validates the detector with safe fixtures.
- `npm run smoke:external-scoped-document-chat`: third-party scoped document live smoke for dataset group authorization, explicit document union, same-conversation scope restore, changed-conversation isolation, and attachment-title scope matching. Use `-- --self-test` to validate deterministic payload/parser fixtures without calling DataMax or requiring a bearer.
- `npm run smoke:customer-web-codex-live`: guarded post-deploy live-smoke harness for Customer Web Codex. Default/preflight mode does not call the network and writes a redacted readiness receipt with `controlledLiveInputChecklist` and `approvalRequestSummary`, so operators can see exactly which live inputs and gates are still missing without exposing values. Add `--allow-missing-gates` only when preflight is being used as a missing-input checklist and should exit 0 despite `readyToExecute=false`; this does not relax live `--execute`. Live mode requires `--execute --ack-controlled-live --approval-id ...` plus a test auth cookie or bearer, controlled test dataset id, and current rendered V3 generated static-page artifact context for `generated_static_page_edit`; operators can supply that context as JSON, a file, or `--current-artifact-public-url https://v3.elepcloud.com/generated-artifacts/...`. Execute receipts include a redacted `preflightSnapshot` proving the gates/checklist were ready before live writes. Preflight rejects placeholder artifact context that lacks a rendered static-page signal and an absolute V3 generated-artifacts seed URL. It covers `customer_complex_request`, `customer_artifact_request`, `generated_static_page_edit`, `generated_static_page_publish`, `v3_product_change_request`, and right-side shelf evidence through assistant-run detail events/artifact bundles.
- `run-ingest-runtime-gate.sh`: non-destructive Linux/deployment-target gate for ingest fallback dependencies; it checks the service `PYTHON_BIN -m markitdown --version` path and fails when the pinned MarkItDown fallback version is missing.
- `run-document-understanding-smoke.sh`: non-destructive local/deployment-target smoke for PaddleOCR parser contracts, low-quality PDF gating, third-party parse compatibility, and resume company/entity scan rules. Set `DOCUMENT_UNDERSTANDING_SMOKE_RUNTIME_GATE=true` to also run the deployment ingest runtime gate.
- `run-data-ingestion-staging-sync-smoke.sh`: non-destructive local/deployment-target smoke for data-ingestion staging plan confirmation, ExternalSourceSync startup/dedup/status feedback, worker materialization, retrieval indexing, and generated third-party guide checks.
- `run-data-ingestion-staging-live-smoke.sh`: non-destructive deployment-target smoke for a stored database source; it reads only V3 PostgreSQL/internal status state and reports source config, sync history, default dataset readiness, alternate ready datasets, chunks, retrieval evidence, and question/report readiness without querying the customer/source database. Set `DATA_INGESTION_LIVE_SMOKE_SELF_TEST=true` to validate the report builder with synthetic V3 status fixtures.
- `npm run smoke:video-ppt-main-visible`: non-destructive main-site release gate for assistant-run-bound video/PPT extraction visibility. It can create a public-video prompt run or reuse an existing `assistant_run_id`; it waits for `video_extraction_summary`, downloads PPTX/Markdown/manifests through `/api/v3/html-artifacts/{artifact_id}/files/{index}`, and validates PPTX OOXML entries plus Markdown/PPTX slide-count agreement.
- `npm run smoke:video-ppt-upload-main`: main-site uploaded-video release gate for video/PPT extraction. Use `-- --self-test` to validate the offline artifact/download contract, including minimal PPTX/Markdown validation and positive/negative video-PPT trigger classification, without calling the network. Use `-- --preflight` before live approval to validate fixture/source shape, video extension support, video-PPT trigger wording, redaction, and live write scope without downloading or uploading. Live mode uploads a public fixture through `/api/v3/local-document-uploads`, registers and ingests the video document through `/api/v3/documents`, creates a dataset-scoped assistant run that asks to extract PPT/slides/courseware, then validates the same PPTX/Markdown/manifest download contract. Running live mode against production writes a controlled smoke upload/document/run record, so use only approved public fixtures.
- `npm run smoke:external-video-ppt`: third-party video registration and special-trigger release gate. Use `-- --self-test` to validate the offline reply/download contract, requested `video_ppt_extraction` payload, supported video extension classifier, positive/negative video-PPT trigger classification, and redaction without calling the network. Use `-- --preflight --allow-missing-bearer` before live approval to validate bearer/context gates, fixture shape, video-PPT trigger payload, redaction, and live write scope without registering documents or posting events.
- `npm run smoke:video-ppt-no-live-rollup`: consolidated no-live gate for video/PPT extraction readiness. Use `-- --self-test` to run the upload-main self-test/preflight, external-video-PPT self-test/preflight, login-gated handoff self-test/preflight, authorized-capture self-test, quality-matrix self-test, Rust formatting check, media-worker video/PPT library tests, offline-smoke binary check, and video-deliverables validator tests in one pass. It does not call DataMax live endpoints, download videos, upload files, create datasets/documents/runs, open browsers, record screens, run FFmpeg capture, deploy services, or touch any server.
- `npm run smoke:video-ppt-handoff`: lightweight WeChat/login-gated video PPT handoff smoke. It validates `wechat_video_login_handoff` or an equivalent third-party unsupported-source card, requires `login_gated_video_source_not_supported` plus upload/direct-URL/authorized-capture next steps, and rejects success/download/artifact-link signals. Default `--self-test` does not call the network; it records no-network/provider/video-fetch/PPT-generation flags and verifies negative fixtures for missing reason, false success/downloads, artifact links, raw source URL leaks, and credential requests. Use `-- --preflight` to validate main/external handoff live gate shape, deployment/bearer requirements, redaction, and lightweight write scope without network calls. Live `--mode main|external|both` writes only lightweight smoke chat/event records and never fetches the source link.
- `npm run smoke:video-ppt-quality-matrix`: deterministic P2-2E quality-matrix self-test and local deliverables review. Use `-- --self-test` to check the fixed synthetic/public/customer matrix shape, `-- --synthetic-deliverables target/<video-extraction>/generated_artifacts` to validate a local generated-artifacts package as the synthetic case, `-- --public-course-deliverables target/<video-extraction>/generated_artifacts` to classify an approved anonymous public-course sample as the public case, and `-- --customer-deliverables target/<video-extraction>/generated_artifacts --customer-approval-id APPROVAL-...` only after explicit customer/operator authorization. Deliverables flags can be combined to produce a complete three-category matrix when all required inputs are present; `--self-test` stays mutually exclusive with deliverables inputs, and customer inputs require an approval id that is not written into the report. It does not call DataMax, download video, upload files, record browser sessions, or deploy services.
- `run-codex-host-workspace-retention-smoke.sh`: non-destructive local/deployment-target smoke for Codex Host task workspace retention manifests and cleanup-candidate reporting; it never deletes workspaces.
- `run-jump-host-codex-shim-smoke.ps1`: jump-host smoke for the Codex host shim.
- `run-jump-host-video-deliverable-smoke.ps1`: jump-host smoke for video/PPT deliverable validation.

Static-page handoff checks:

- `npm run test:static-page-export-artifact`: unit coverage for the reusable static-page export artifact validator.
- `npm run validate:static-page-export-artifact -- --artifact target/static-page-render-smoke/<artifact-dir>`: validates a generated static-page export directory outside the smoke runner.

External integration checks:

- `bash scripts/run-external-direct-reply-smoke.sh`: Rust smoke coverage for the external ordinary-chat direct-reply contract, provider fallback/timeout behavior, SSE started/delta/completed semantics, and low-quality PDF parse gating.
- `npm run smoke:newbai-customer-answer-live-capture -- --self-test`: deterministic no-network harness for producing NewBai customer-answer result JSONL and feeding it into the evaluator. Use `-- --preflight --dataset-external-ids <id>` to validate live payload shape without network calls. Live mode requires `--run-live --ack-controlled-live --bearer <token> --dataset-external-ids <id>` and defaults to skipping template-reuse guard prompts unless explicitly included.
- `npm run smoke:external-report-export`: live external-channel smoke for report/static-page delivery. It checks JSON and SSE report cards, one customer-facing report link, export fields, `download_exports[]`, and non-empty generated artifact files. Use `-- --self-test` for the deterministic offline report-surface contract.
- `npm run smoke:external-report-focus`: deterministic offline smoke for Xinbai report trigger/focus routing, ordinary-QA guards, primary-template reuse, and one-link report surfaces.
- `npm run smoke:newbai-customer-answer -- --self-test`: deterministic offline evaluator for NewBai customer-answer result JSONL. The wrapper `bash scripts/run-newbai-customer-answer-smoke.sh` runs the same evaluator against the bundled fixture samples and writes JSON/Markdown receipts.
- `npm run smoke:external-video-ppt`: third-party video/PPT extraction smoke. It registers a public or loopback video fixture through `/v1/external/channels/{connection_id}/documents/parse`, sends a scoped `/events` message that explicitly asks to extract PPT/slides/courseware already shown in the video, polls the assistant-run reply, and validates the third-party video extraction card plus optional PPTX/Markdown/manifest downloads. Use `-- --self-test` for the deterministic offline reply-surface contract plus minimal PPTX/Markdown validation. Use `-- --preflight` to validate third-party context, fixture/source shape, trigger payload, redaction, and live write scope without network calls; live mode still requires an approved inbound bearer.
- `npm run test:pure-third-party-guide-html`: checks the current public HTML/Markdown integration guides and their published `/external-integrations/...` copies.
