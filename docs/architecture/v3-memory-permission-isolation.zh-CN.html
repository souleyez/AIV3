DataMax 企业记忆与权限隔离说明

DataMax 的企业记忆由平台侧统一管理，不依赖模型厂商侧长期记忆，也不将企业资料作为模型持久化记忆保存。模型仅在单次请求中接收 DataMax 明确提供的临时上下文，用于组织最终回答。

DataMax 不依赖模型侧记忆。每次模型调用均为无状态请求，显式关闭 provider 侧存储，不复用 provider 侧会话线程；企业记忆、会话授权和资料范围均由 DataMax 平台侧恢复和裁剪后临时提供给模型。

平台侧记忆 企业知识、文档解析、事实抽取、会话授权和产物状态由 DataMax 数据库、对象存储、索引与权限系统维护。
受控供料 DataMax 不向模型提供完整资料库、完整文档集合或完整检索结果，只提供与本轮问题相关的证据包。
并发隔离 同一个模型并发处理多个用户请求时，每次调用都由 DataMax 显式构造独立上下文，不共享企业资料记忆。

Position

1. 定位

DataMax 的企业记忆系统由平台侧统一管理，不依赖模型厂商侧的长期记忆能力，也不将企业资料作为模型持久化记忆保存。

企业知识、文档解析结果、数据集关系、第三方会话授权、事实抽取结果、问答证据、静态页产物状态等，均由 DataMax 自有数据库、对象存储、索引系统和权限系统维护。

模型只在单次请求中接收 DataMax 明确提供的临时上下文，用于组织最终回答。模型调用结束后，本轮上下文不会成为模型侧长期记忆。

DataMax 不依赖模型侧记忆。每次模型调用均为无状态请求，显式关闭 provider 侧存储，不复用 provider 侧会话线程；企业记忆、会话授权和资料范围均由 DataMax 平台侧恢复和裁剪后临时提供给模型。
Third-party Boundary

2. 第三方接入后的上下文边界

第三方系统接入后，DataMax 按以下字段建立身份、会话和资料授权边界。

字段 含义
tenant_external_id 第三方租户或客户边界。
bot_external_id 第三方机器人或应用边界。
conversation_external_id 会话边界。同一会话下可持续使用此前传入的授权上下文。
sender_external_id 第三方用户身份边界。
dataset_external_ids 本会话授权使用的资料分组。
available_document_external_ids / documentExternalId 本会话授权使用的具体文档。

当第三方在某个 conversation_external_id 下传入数据集或文档授权后，DataMax 会在该会话范围内持续保留该授权上下文。后续同一会话可以继续使用已授权资料；当会话 ID 变化时，授权范围重新计算。

第三方内部如何判断用户能访问哪些资料，由第三方系统负责。DataMax 以第三方传入的授权范围作为本轮和本会话的可用资料边界，并在 DataMax 内部继续执行租户、会话、数据集、文档和产物级隔离。

Execution Workflow

3. 问答执行机制

DataMax 的问答流程不是将完整资料库、完整文档或完整检索结果直接提供给模型，而是采用平台侧受控供料机制。

01
接收请求 DataMax 接收用户问题及第三方传入的身份、会话和资料授权信息。
02
问题理解 模型先用于理解问题意图，并判断任务类型，例如文档问答、统计分析、排序汇总、表格查询、静态页生成或普通问答。
03
本地智能体检索 DataMax 本地智能体根据任务类型，在当前授权范围内执行检索、事实查询、表格分析、文档细节读取或数据快照查询。
04
证据处理 DataMax 对候选内容进行权限校验、证据裁剪、结构化整理和上下文压缩。
05
受控供料 DataMax 仅向模型提供与本轮问题相关的证据摘要、必要片段、结构化事实、表格结果和来源定位。
06
生成回答 模型基于 DataMax 提供的受控证据组织最终回答，并返回给第三方用户。
模型不直接获得完整企业资料，也不承担企业记忆存储职责。模型只根据本次请求中 DataMax 提供的临时上下文完成回答生成。
Local Agent

4. 本地智能体职责

DataMax 本地智能体不是企业记忆的持久化载体，也不是最终答案的唯一生成者。它承担的是平台侧的受控检索和上下文组织工作。

问题拆解 识别查询对象、指标、时间、维度、格式和任务类型。
范围选择 根据会话和资料授权边界选择可用数据集、文档、事实表或结构化数据。
受控查询 在授权范围内执行检索、事实聚合、表格分析和文档细节读取。
证据裁剪 对候选证据进行去噪、裁剪、合并和来源标注。
证据供给 将必要证据包提供给模型，由模型组织自然语言回答。
非完整喂入 不把完整检索内容、完整知识库或完整文档集合交给模型。
Concurrency Isolation

5. 并发隔离

DataMax 不使用模型侧长期记忆，因此同一个模型服务并发处理多个用户问题时，不会因模型记忆共享导致上下文串场。

每一次模型调用都由 DataMax 显式构造独立上下文，包括当前租户、当前机器人或应用、当前会话、当前用户、当前授权的数据集和文档、当前检索或聚合得到的证据，以及当前允许引用的事实范围。

模型调用之间不共享 DataMax 企业资料上下文。模型侧不会因为服务多个用户而自动记住其他用户的资料、文档或历史问答。

Session Memory

6. 会话记忆与权限复核

DataMax 可以在平台侧保留会话上下文和授权状态，但这属于 DataMax 自身的会话记忆，不属于模型厂商侧记忆。

当用户在同一 conversation_external_id 下继续提问时，DataMax 可以恢复该会话此前授权的数据集、文档和上下文摘要。恢复前仍需满足以下条件：

  • 租户边界一致；
  • 机器人或应用边界一致；
  • 会话 ID 一致；
  • 第三方传入或此前确认的授权范围仍有效；
  • DataMax 内部资料、产物和任务状态仍可用。

如果会话 ID 变化，或者资料授权发生变化，DataMax 会重新计算可用范围，不默认继承其他会话的资料。

Security Principles

7. 安全原则

  • 不使用模型厂商侧长期记忆保存企业资料；
  • 不向模型提供完整资料库、完整文档集合或完整检索结果；
  • 不跨租户、跨会话、跨用户共享未授权上下文；
  • 不因模型并发调用产生用户资料串场；
  • 所有可引用内容必须来自当前授权范围内的 DataMax 证据供料；
  • 企业知识的存储、更新、去重、解析深化和权限控制均由 DataMax 平台侧完成。
