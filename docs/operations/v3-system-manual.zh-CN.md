# DataMax V3 企业智能体平台方案说明书

**版本日期：** 2026-07-11
**适用范围：** DataMax V3 主站、管理台、第三方接口、文档知识库、数据库接入、报表和静态页产物、分布式 Codex 执行器阵列、行业版 Codex 客户端。  
**文档定位：** 本说明书面向企业客户方案沟通和内部交付设计，是 DataMax V3 帮助企业规模化、安全化、可审计地使用世界顶尖智能体 Codex 的最佳实践底稿。对外发布时应删除运维、执行器调度、模型路由、观测密钥和内部排障内容。

## 1. 系统定位

DataMax V3 是面向企业资料、业务数据和第三方系统的企业级智能体数据平台。系统把文档、数据库、会话上下文、模板技能、Codex 执行能力和生成产物统一放到数据集链路里处理，让企业用户可以在同一个入口完成问答、资料检索、经营分析、报表生成、静态页发布和复杂任务执行。

从企业客户视角看，DataMax V3 的核心价值不是简单接入一个聊天模型，而是把 Codex 这类世界顶尖智能体纳入企业可控的数据、权限、审计、产物和执行体系。企业既能获得顶尖智能体的一键执行能力，又能保留自己的数据中心、权限边界、行业模板、产物资产和合规要求。

企业级最佳实践：

- 用 V3 数据中心统一管理企业数据集、文档、数据库、模板、权限和产物。
- 用 Codex 执行器阵列承接复杂任务，避免把所有重任务堆在普通问答链路里。
- 用行业版 Codex 客户端把智能体能力带到客户本地，支持本地文件、本地系统和私有数据中心直联。
- 用任务编排、审计、临时授权和产物回传机制，让智能体执行可控、可追踪、可复用。
- 用自有 Mac mini 阵列、客户专属节点和云端兜底形成企业级弹性执行池。
- 用数据集和产物同步机制，把智能体完成的页面、报表、脚本、分析结果沉淀为企业资产。

核心目标：

- 支撑主站用户直接上传资料、选择数据集、提问和生成报表。
- 支撑第三方系统通过接口传入文档、会话、用户、数据集范围和业务库范围。
- 支撑数据库源接入后清洗到 DataMax 数据集，再用于问答、分析和可视化报表。
- 支撑已有产物复用和持续修改，避免每次需求变更都重新设计。
- 支撑异步任务、流式进度、最终产物链接和后台结果补发。
- 支撑复杂任务转派给分布式 Codex 执行器阵列，由自有节点或客户本地节点完成重任务。
- 支撑行业版 Codex 客户端直联客户 V3 数据中心，在本地使用智能体工具并同步产物和数据集结果。

| `https://v3.elepcloud.com/admin/external-integrations` | 第三方通道和外部集成观测页。 |

## 3. 核心对象

| 对象 | 说明 |
| --- | --- |
| 租户 | 企业或第三方通道所属的隔离单元。 |
| 用户 | 主站用户或第三方传入的 `sender_external_id`。可用于后续用户上下文和历史会话判断。 |
| 会话 | 一轮连续对话。第三方用 `conversation_external_id` 维持上下文和文档授权范围。 |
| 数据集 | DataMax 的核心资料容器。文档、数据库同步结果、报表和静态页都围绕数据集运行。 |
| 文档 | 用户上传或第三方接口传入的文件。支持解析、入库、检索、问答和移动数据集归属。 |
| 数据库源 | 外部 MySQL 等业务库接入记录。同步后进入数据集，用于分析和报表。 |
| 技能 | 第三方或主站触发的特定能力，例如模板输出、订单截图字段抽取、报表生成。 |
| 产物 | 系统生成的静态页、HTML、CSV、PPT、Markdown、图片预览和数据快照。 |
| Codex 执行器中转站 | V3 的复杂任务调度层，负责把任务分发给可用 Codex 节点并回收结果。 |
| Codex 节点 | 安装独立 Codex 和节点代理的执行机器，可来自 Mac mini 阵列、云端节点或客户本地客户端。 |
| 行业版 Codex 客户端 | 面向客户下载的一键智能体工具，可直联客户 V3 数据中心执行本地任务并同步产物。 |

## 4. 主站使用流程

### 4.1 资料问答

1. 用户进入 `https://doc.elepcloud.com/`。
2. 上传文档或选择已有数据集。
3. 系统完成快速解析和入库，后台继续做详细解析。
4. 用户直接提问。
5. DataMax 根据用户权限、选中数据集、文档解析状态和检索证据组织回答。

注意：

- 主站“选中数据集”表示当前用户明确选择的资料范围，不再区分额外的“预选状态”。
- 选中范围用于加快和聚焦回答，但不应错误地把用户有权限的资料排除到不可访问范围之外。
- 如果当前问题需要更多资料，系统应优先扩展供料或引导用户补充信息，而不是直接返回系统兜底话术。

### 4.2 报表和静态页

1. 用户提出报表、经营分析、可视化页面或静态页需求。
2. 系统识别当前数据集、数据库源、历史产物和用户最新意图。
3. 如果该数据集已有被认可的产物，默认在原产物基础上修改。
4. 只有用户明确要求重新设计时，才重新走完整设计链路。
5. 生成完成后返回可点击的公开页面链接，并在右侧保留项目卡片用于继续查看和修改。

### 4.3 在线修改

用户可在对话里明确提出“修改报表”。系统应把该请求识别为对已有产物的编辑，不应重新创建无关页面。修改优先级按用户最新表达处理，例如用户要求“门店取高”时，应把相关模块前置，而不是机械复用旧模板顺序。

### 4.4 服装设计图片资产异步解析

主站资产导入成功后，图片解析不在 API 请求内同步执行。开启解析开关时，平台会向现有 `ingest` 队列写入 `parse_asset_profile` 任务，由 `ingest-worker` 读取同租户下的资产、parse run 和已批准的本地对象定位信息，再调用现有视觉结构化 provider。默认配置如下：

```text
ASSET_PARSE_ENABLED=false
ASSET_PARSE_MAX_ATTEMPTS=2
ASSET_PARSE_PROVIDER_TIMEOUT_MS=120000
```

运行规则：

- API 和 worker 都会校验 `ASSET_PARSE_ENABLED`；缺失或无法解析时按关闭处理。关闭时资产仍可导入，但不新增解析任务，手工或遗留任务也不得调用 provider。
- 同一租户、资产、parser 名称和版本最多存在一个 `queued`/`claimed` 任务；重复导入不会重置已完成、部分完成或失败的 parse run。
- 完整规范化画像写入 parser 版本隔离的 profile 后标记 `completed`；字段不完整但结果安全可用时写入独立 profile 并标记 `partial`。
- provider 暂时不可用时标记 `retrying`，最多消费两次；永久拒绝、安全校验失败或重试耗尽后写入脱敏错误码并标记 `failed`。
- parser 版本变化会创建新的 parse run 和 profile 版本，不覆盖旧版本已接受画像。
- 只允许读取批准目录内的本地 PNG/JPEG/WebP，执行路径、对象定位信息、图片字节和 provider 原始响应不写入任务 payload、日志、共享回执或 profile。
- 远程 URL 固定返回 `remote_source_disabled`，在 SSRF、重定向、DNS、MIME、大小和超时保护全部落地前不得发起网络抓取。

发布时必须先以 `ASSET_PARSE_ENABLED=false` 部署并回归普通文档 ingest；只有在独立审批窗口内才可对单一测试租户和单张测试图片开启解析。窗口结束后重新关闭开关并重启 `platform-api` 与 `ingest-worker`。

## 5. 文档知识库

### 5.1 支持内容

文档知识库用于处理：

- Word、PDF、Excel、PPT 等办公文件。
- ZIP 中的批量资料。
- 第三方通过 URL 传入的文档。
- 图片类附件和截图抽取场景。
- 视频或演示素材的登记和特殊抽取任务。

### 5.2 解析流程

文档进入系统后通常经历：

1. 创建文档记录。
2. 下载或接收文件。
3. 快速解析，尽快得到基础文本和分类。
4. 入库为可检索证据。
5. 后台进行详细解析、实体提取、段落理解、表格识别和质量检查。
6. 如果解析质量不足，可触发 OCR 或 VLM 兜底。

可用于问答的基本条件：

- 文档生命周期达到可检索状态。
- 文本片段数量大于 0。
- 检索证据数量大于 0。
- 解析质量没有明显失败。

### 5.3 数据集归属

同一文档可以属于多个数据集。主站数据集页面应支持：

- 勾选文档后显示该文档所在的全部数据集。
- 点击未选数据集，把文档加入该数据集。
- 点击已选数据集，把文档移出该数据集。
- 不因为移动分组而重复下载或重复解析同一文档。

第三方文档默认属于第三方系统账户和第三方私有资料范围，普通主站资料库不应默认可见。

## 6. 数据库接入

数据库接入的目标不是让模型直接访问数据库密码或任意执行 SQL，而是把外部业务库纳入 DataMax 数据集链路。

典型流程：

1. 创建数据库源，记录业务库 ID、连接方式、库名、表白名单和同步策略。
2. 测试连接，只返回可用状态，不返回密码。
3. 读取 schema、字段、样例行和统计摘要。
4. 形成字段理解、口径说明和同步计划。
5. 同步清洗后的数据进入目标数据集。
6. 后续问答、报表和静态页都基于该数据集或业务库 ID 执行。

安全要求：

- 生产建议使用服务端密钥引用，例如环境变量或密钥管理系统。
- 如果第三方只能先传账号密码，DataMax 不应把明文凭据写入 PostgreSQL、日志或模型上下文。
- 不允许把完整数据库 dump、原始客户行、数据库 URL 或密码暴露给模型或接口响应。
- 生产写入、schema 修改和真实同步任务应有人工确认或明确授权。

第三方聊天中可用 `business_datasource_ids` 指定本轮业务库范围，也可使用同步后的 `dataset_external_ids` 指定数据集范围。

## 7. 第三方集成

### 7.1 最小接入顺序

1. 创建第三方通道并获取入站 token。
2. 调用文档解析接口，把普通文档、模板文档或资料库文档解析入 DataMax。
3. 聊天时传用户 ID、会话 ID、文档范围、数据集范围、默认提示词和输出格式。
4. 如需报表，传模板或在对话里表达报表生成需求。
5. 等待同步响应、流式进度、轮询状态或回推结果。

### 7.2 聊天事件

核心接口：

```http
POST /v1/external/channels/{connection_id}/events
Authorization: Bearer <DataMax inbound token>
Content-Type: application/json
```

常用字段：

| 字段 | 说明 |
| --- | --- |
| `platform` | 第三方平台标识。 |
| `tenant_external_id` | 第三方租户 ID。 |
| `bot_external_id` | 第三方机器人或应用 ID。 |
| `conversation_external_id` | 第三方会话 ID，同一会话用于持续复用上下文和文档范围。 |
| `sender_external_id` | 第三方用户 ID。 |
| `message_external_id` | 第三方消息 ID，用于幂等。 |
| `message_type` | 消息类型，例如 `text`、`image`。 |
| `text` | 用户本轮消息文本。 |
| `default_prompt` | 第三方给 DataMax 的默认提示词。 |
| `output_format` | 输出格式，例如 `rich_text`、`image_text`、`markdown_table`、`json`。 |
| `available_document_external_ids` | 本轮或本会话允许使用的文档 ID 列表。 |
| `dataset_external_ids` | 本轮或本会话允许使用的数据集/资料库 ID 列表。 |
| `business_datasource_ids` | 本轮允许使用的业务数据库源 ID 列表。 |
| `requested_skills` | 第三方希望本轮应用的技能列表。 |
| `attachment_refs` | 附件引用。可传对象数组，也兼容图片或文件 URL 字符串数组。 |
| `idempotency_key` | 幂等键，建议包含租户、会话和消息 ID。 |

同一 `conversation_external_id` 下，第三方首次传入文档范围或数据集范围后，后续消息可以继续复用，直到第三方更换会话 ID 或重新传入新的范围。

### 7.3 输出格式

第三方可通过 `output_format` 选择期望输出形态：

| 值 | 用途 |
| --- | --- |
| `rich_text` | 默认富文本回答。 |
| `image_text` | 图文排版或卡片式内容。 |
| `markdown_table` | 表格优先输出。 |
| `json` | 结构化字段输出，适合入库。 |

当用户上传订单、充值记录、支付记录等截图时，建议使用 `message_type: "image"`、`output_format: "json"`，并把图片放入 `attachment_refs`。如需强制订单截图抽取，可在 `requested_skills` 中传 `skill_id: "order_screenshot_extract"`。系统应返回可入库字段，而不是只返回自然语言描述。

### 7.4 流式和异步结果

第三方可使用：

```http
POST /v1/external/channels/{connection_id}/events/stream
Accept: text/event-stream
```

流式事件应覆盖：

- 准备按什么意图或提示词处理。
- 正在检索哪些范围的资料或数据源。
- 正在生成设计、报表或静态页。
- 中间产物是否已生成。
- 后续还会执行什么。
- 失败时说明失败阶段、是否可重试、是否已有可用中间结果。

如果任务超过第三方页面等待时间，DataMax 应返回 `status_url`、`poll_after_seconds` 或可回推的最终结果。已完成的异步任务应能主动补发最终助手回复，避免用户看到“处理中”后没有结果。

## 8. 报表和静态页产物

### 8.1 产物类型

DataMax 支持生成：

- HTML 静态页。
- 可视化经营报表。
- 数据表 CSV。
- Markdown 报告。
- PPT 报告。
- 数据快照 JSON。
- 图片预览或设计草图。

标准公开链接通常位于：

```text
https://v3.elepcloud.com/generated-artifacts/...
```

### 8.2 生成原则

- 数据口径优先，页面效果不能覆盖真实数据含义。
- 状态型指标应使用最新快照，不应误把重复快照累计成总量。
- 趋势图可以使用多个日期，但必须标识为时间序列。
- 重点模块应根据用户最新意图排序，关键指标放在首屏可见位置。
- 数据不足不能直接失败，应先扩大供料、降低模块复杂度或按已有数据出可解释版本。
- 第三方不能长时间等待时，应先返回处理中状态和后续查询方式，完成后补发链接。

### 8.3 复用和修改

同一数据集或同一业务主题已经有客户认可的产物时，默认在原产物基础上改。只有出现以下情况才重新设计：

- 用户明确说“重新设计”“换一种风格”“重新生成一版”。
- 原产物和当前数据集、权限或主题明显不匹配。
- 原产物缺少关键结构，无法承载本轮需求。

对话里出现“修改报表”应严格触发已有产物修改流程。

## 9. 模板和技能

模板可以来自：

- 系统内置模板。
- 用户指定的文档模板。
- 第三方传入的模板文档。
- 已发布且被认可的历史产物。

模板技能的基本原则：

- 模板负责结构、字段组织和版式参考。
- 事实内容仍以本轮授权资料、数据库源和检索证据为准。
- 不应因为模板存在就跳过数据口径校验。
- 第三方如果传入多个技能，DataMax 应结合用户意图判断优先级；`required` 技能必须尽量执行，无法执行时返回明确原因。

## 10. 管理台和观测

管理台用于：

- 查看主工作台。
- 查看第三方通道。
- 创建、启用、轮换第三方通道 token。
- 查看第三方事件、对话测试、队列和任务状态。
- 查看静态页、模型路由和异步任务的脱敏状态。

访问规则：

- `/admin` 需要管理登录。
- `/admin/external-integrations` 需要管理登录。
- 页面内敏感观测和通道操作仍应使用观测密钥或二级权限。
- 公开接口文档不应因为管理台鉴权而无法访问。

观测内容必须脱敏，不记录：

- bearer、cookie、provider key、数据库密码。
- 原始客户行、完整文档正文、私有对象路径。
- 原始供应商 payload。
- 数据库 URL 和下载临时签名。

## 11. 权限和安全

### 11.1 主站权限

主站按用户权限读取可访问的数据集、文档和产物。用户选择数据集后，回答应优先使用选中范围；但不能因为内部“预选”误判导致用户有权限的数据不可用。

### 11.2 第三方权限

第三方通道按连接隔离：

- 每个第三方通道有独立入站 token。
- 第三方文档默认进入该通道系统账户，普通主站资料库不默认可见。
- 第三方传入的文档范围、数据集范围和业务库范围绑定到会话。
- DataMax 按第三方传入的范围供料，不替第三方扩大内部业务权限。

### 11.3 产物权限

静态页产物可以生成公开链接，但生成前必须确认：

- 数据来源是当前用户或第三方授权范围。
- 页面没有泄露原始密钥、内部路径或未授权字段。
- 如果面向不同角色，例如总部和分店店总，应支持不同链接、不同数据视角或不同过滤范围。

## 12. 模型、执行器和任务转派

DataMax 的原则是平台掌握权限、数据、任务编排和产物发布，模型和执行器只处理被平台裁剪后的上下文、证据、工具结果和任务说明。

执行链路包括：

- 主站对话模型。
- 第三方对话模型。
- 文档解析和质量兜底模型。
- 图片和截图字段抽取模型。
- 静态页和报表生成执行器。
- 本地优先的静态页发布链路。
- 云端执行器兜底链路。
- 分布式 Codex 执行器阵列。
- 客户本地行业版 Codex 客户端。

转派原则：

- 普通短问答优先在 V3 主系统直接完成。
- 已有检索证据可快速回答的问题不转派。
- 报表、静态页、深度数据分析、多文件理解、脚本生成、自动化操作等复杂任务可转派给 Codex 执行器。
- V3 先判断用户权限、数据集范围、业务库范围和任务风险，再生成任务包。
- Codex 节点只拿本次任务所需的最小上下文、临时凭证和限定工具。
- 结果必须回传 V3，由 V3 做验收、脱敏、归档、发布和数据集同步。

执行器不得获得：

- 数据库明文密码。
- 未授权文档。
- 任意服务器文件写权限。
- 用户可控 CLI 参数。
- 原始 provider key 或浏览器 token。
- 超出本次任务范围的长期数据集访问权。

## 13. 分布式 Codex 执行器阵列和行业版客户端

### 13.1 定位

分布式 Codex 执行器阵列是 V3 面向企业客户的复杂任务执行层，也是企业规模化使用世界顶尖智能体 Codex 的关键实践。它不替代 V3 主系统，也不替代客户数据中心；它负责把适合智能体执行的任务分发给可控 Codex 节点，由节点完成资料分析、代码生成、报表修订、静态页生产、自动化操作和行业工具调用。

对企业客户而言，这一层解决的是“怎么把强大的个人智能体能力变成企业可管理、可分配、可审计、可复用的生产力系统”：

- 个人使用 Codex 解决单点任务，V3 把 Codex 组织成企业执行网络。
- 单台机器使用 Codex 容易受限于设备、人员和上下文，V3 用节点池承载并发任务和长期任务。
- 普通智能体工具缺少企业数据权限，V3 用数据集、临时授权和审计记录控制访问边界。
- 普通产物容易散落在个人电脑，V3 把产物同步回企业数据中心并沉淀到数据集。
- 企业客户可以同时使用云端能力、自有 Mac mini 阵列和本地行业版 Codex，按数据敏感度和任务类型选择执行位置。

核心目标：

- 用 Mac mini 阵列或其他自有机器承载独立 Codex 节点，形成可横向扩展的执行池。
- 客户复杂任务可从 V3 主系统转给 Codex 节点执行，主系统不用长时间阻塞。
- 每个节点空闲时可分担 V3 主系统的访问、排队和重任务执行压力。
- 提供行业版 Codex 客户端，允许客户一键使用本地智能体工具。
- 行业版 Codex 可直联客户自己的 V3 数据中心，执行结果、产物和数据集变更按协议同步。
- 保持 DataMax/V3 作为权限、数据集、审计和产物归档的唯一权威中心。
- 形成企业客户使用 Codex 的标准化方案：统一入口、统一权限、统一调度、统一审计、统一产物沉淀。

### 13.2 总体架构

```text
用户 / 第三方 / 主站
        |
        v
DataMax V3 数据中心
  - 租户 / 用户 / 权限
  - 数据集 / 文档 / 数据库源
  - 任务编排 / 产物发布
  - 审计 / 观测 / 回调
        |
        v
Codex 执行器中转站
  - 任务接收
  - 节点注册
  - 调度策略
  - 队列和重试
  - 执行凭证下发
  - 结果验收
        |
        v
Codex 节点池
  - Mac mini 阵列
  - 云端执行节点
  - 客户本地行业版 Codex
  - 专用行业工具节点
```

角色划分：

| 角色 | 职责 |
| --- | --- |
| DataMax V3 主系统 | 用户入口、权限判断、数据集选择、任务生成、结果展示、产物发布。 |
| Codex 执行器中转站 | 任务队列、节点调度、租户隔离、执行状态、失败重试、结果接收。 |
| Codex 节点 | 实际执行复杂任务。每台机器安装独立 Codex 和节点代理。 |
| Mac mini 阵列 | 自有长期在线执行资源，适合承载高频复杂任务和静态页生产。 |
| 行业版 Codex | 面向客户下载的一键使用客户端，内置行业工具、模板和 V3 数据中心连接。 |
| 客户 V3 数据中心 | 客户私有数据、文档、数据库、产物和审计的权威存储。 |
| 管理台 | 查看节点、队列、任务、租户用量、失败原因和产物同步状态。 |

### 13.3 适合转派的任务

适合转给 Codex 执行器的任务：

- 高质量静态页和报表生成。
- 既有页面或报表的在线修改。
- 数据库字段理解、指标口径整理和报表规划。
- 大文档、多文档、ZIP 资料的深度理解。
- 行业模板适配，例如养老、商业经营、招聘、工程人员、外卖员训练等。
- 客户本地文件、表格、图片和业务系统的半自动处理。
- 代码生成、数据清洗脚本、ETL 草案、导出转换和自动化工具。
- 需要浏览器、文件系统、Office、脚本运行或多步骤检查的任务。

不适合直接转派的任务：

- 普通短问答。
- 已有检索证据可以快速回答的问题。
- 只需要简单格式转换的轻任务。
- 未授权数据访问。
- 需要客户明确确认的生产写入、schema 修改、删除、覆盖发布。

### 13.4 Mac mini 阵列

每台 Mac mini 作为一个独立 Codex 节点运行：

- 安装独立 Codex。
- 安装节点代理。
- 注册到中转站。
- 上报 CPU、内存、磁盘、网络、可用模型、工具能力和当前负载。
- 接收中转站下发的任务包。
- 在隔离工作目录执行任务。
- 将结构化结果、日志摘要和产物回传中转站。
- 空闲时接受 V3 主系统的后台重任务。

建议节点分层：

| 节点类型 | 用途 |
| --- | --- |
| 通用执行节点 | 文档理解、代码生成、报表修订、简单自动化。 |
| 静态页节点 | 负责高质量 HTML、CSS、数据绑定和截图校验。 |
| 数据分析节点 | 负责数据库画像、指标计算、聚合查询、CSV/PPT/MD 导出。 |
| 行业节点 | 预装行业模板、领域工具和常用数据结构。 |
| 客户专属节点 | 只服务某个客户或某个私有部署，避免跨租户混用。 |

### 13.5 行业版 Codex 客户端

行业版 Codex 是面向客户下载的一键使用智能体工具。客户不需要自己理解底层模型、脚本、插件和执行目录，只需要登录或绑定自己的 V3 数据中心，即可使用行业能力。

行业版 Codex 的企业客户价值在于：把世界顶尖智能体工具从“技术人员个人工具”升级为“企业可落地的行业工作台”。客户可以在本地安全使用智能体处理文档、表格、页面和业务系统，又能把确认后的结果同步回企业 V3 数据中心，成为可复用、可追溯、可继续修改的企业资产。

典型能力：

- 一键连接客户 V3 数据中心。
- 自动读取被授权的数据集、文档、模板和数据库源。
- 在本地执行资料分析、报表编辑、静态页修改和自动化操作。
- 产物自动同步回客户 V3 数据中心。
- 支持客户本地文件和系统数据，不必先上传到公网。
- 支持行业模板和固定技能包，例如门店经营分析、养老机构运营、招聘简历分析、培训资料生成。

行业版 Codex 的定位：

- 是客户本地的智能体工作台。
- 是 V3 数据中心的本地执行延伸。
- 不是绕过 V3 权限的数据访问工具。
- 不是把客户数据默认上传到平台的同步工具。

### 13.6 数据和产物同步

Codex 节点可获取的数据来源：

- V3 下发的任务说明。
- V3 裁剪后的上下文和检索证据。
- 临时授权的数据集片段。
- 临时授权的文档下载地址。
- 临时授权的数据库查询结果或聚合摘要。
- 客户本地行业版 Codex 允许访问的本地文件。

默认禁止：

- 直接拿数据库明文密码。
- 读取未授权数据集。
- 拉取完整客户库 dump。
- 在任务文本中暴露长期 token。
- 把本地客户文件无条件上传到中心。

Codex 节点应返回结构化结果：

| 输出 | 说明 |
| --- | --- |
| `summary` | 本次执行摘要。 |
| `status` | `completed`、`failed`、`needs_confirmation`、`partial_completed`。 |
| `artifact_manifest` | 产物清单，例如 HTML、图片、CSV、PPT、MD、JSON。 |
| `dataset_updates` | 建议同步到数据集的结构化结果。 |
| `evidence` | 关键数据来源和口径摘要。 |
| `warnings` | 数据不足、权限不足、字段不确定、需要人工确认。 |
| `next_actions` | 可继续执行的修改或发布动作。 |

V3 接收后负责：

- 校验任务和租户匹配。
- 校验产物没有越权数据。
- 保存产物。
- 更新数据集或等待确认。
- 生成公开链接或私有链接。
- 回写对话、流式进度和第三方回调。

### 13.7 调度和空闲回流

中转站调度时应考虑：

- 租户隔离。
- 节点在线状态。
- 节点能力标签。
- 当前队列长度。
- 任务超时时间。
- 数据所在地。
- 是否需要本地文件访问。
- 是否需要浏览器、Office、脚本、数据库或图像工具。
- 客户 SLA 和任务优先级。

基础调度规则：

1. 客户专属任务优先投递到客户专属节点。
2. 需要本地数据的任务优先在客户本地行业版 Codex 执行。
3. 需要静态页和截图校验的任务优先投递到静态页节点。
4. 通用任务投递到负载最低且能力匹配的节点。
5. 节点长时间无响应时转移到同能力节点。
6. 高风险任务返回确认，不自动执行写入或覆盖。

每台 Codex 节点空闲时，可以作为 V3 主系统的弹性执行资源。

可回流任务：

- 静态页 HTML 生成和修改。
- 旧产物重渲染。
- 文档深解析。
- 数据集摘要和企业记忆更新。
- 报表模板预热。
- 回归测试和截图校验。
- 低优先级批处理。

回流原则：

- 不抢占客户正在使用的本地任务。
- 不跨租户混用私有数据。
- 节点必须声明可接受的平台任务类型。
- 中转站应支持资源配额，避免单个客户或单类任务占满阵列。
- 空闲回流任务必须可中断、可重试、可恢复。

### 13.8 客户侧流程

云端 V3 转派流程：

1. 用户在 V3 主站或第三方系统提出复杂任务。
2. V3 判断该任务适合 Codex 执行器。
3. V3 生成任务包和最小上下文。
4. 中转站选择合适节点。
5. Codex 节点执行任务。
6. 结果回传中转站。
7. V3 验收、归档、生成链接或继续追问确认。
8. 用户在原对话里收到结果和可继续修改入口。

行业版 Codex 本地执行流程：

1. 客户下载行业版 Codex。
2. 客户绑定自己的 V3 数据中心。
3. 客户选择行业模板、数据集或本地文件。
4. Codex 在本地执行任务。
5. 结果可本地预览。
6. 客户确认后同步到 V3 数据中心。
7. V3 生成数据集记录、产物链接和审计记录。

### 13.9 管理台能力

管理台应支持：

- 节点列表。
- 节点在线状态。
- 节点能力标签。
- 队列长度。
- 当前任务。
- 历史任务。
- 失败原因。
- 租户用量。
- 产物同步状态。
- 节点版本。
- 行业版 Codex 下载和更新状态。
- 节点空闲回流开关。

敏感信息只展示脱敏摘要，不展示密钥、原始任务包、原始客户文件或数据库连接。

### 13.10 第一阶段落地建议

第一阶段只做最小可用闭环：

1. 建立中转站任务表和节点表。
2. 每台 Mac mini 安装 Codex 和节点代理。
3. 节点注册并定时心跳。
4. V3 支持把固定任务投递到中转站。
5. 中转站支持任务领取、执行、回传和失败重试。
6. 产物回传 V3，统一进入 `generated-artifacts`。
7. 管理台展示节点状态和任务状态。
8. 只开放静态页修改、报表生成、数据分析草案三类任务。
9. 不开放生产写入、删除、覆盖和无限制本地文件访问。

第一阶段验收：

- 至少 2 台节点同时在线。
- V3 可投递任务到指定节点或自动调度节点。
- 节点故障后任务可转移或重试。
- 产物能回传 V3 并生成链接。
- 任务日志不含密钥、数据库 URL、完整文档正文和原始客户行。
- 空闲节点能执行一个后台低优先级任务。

V3 生产主要运行在 8 服务器，典型服务包括：

| 服务 | 用途 |
| --- | --- |
| `aiv3-platform-api.service` | 后端 API 和核心业务接口。 |
| `aiv3-web.service` | Next.js 主站和管理台。 |
| `aiv3-assistant-run-worker.service` | 助手任务和异步运行。 |
| `aiv3-chat-session-worker.service` | 会话相关后台任务。 |
| `aiv3-static-page-worker.service` | 静态页、效果图和产物发布后台任务。 |

常用健康检查：

```bash
systemctl is-active aiv3-platform-api.service aiv3-web.service aiv3-assistant-run-worker.service aiv3-chat-session-worker.service aiv3-static-page-worker.service aiv3-ingest-worker.service
curl -fsS https://v3.elepcloud.com/readyz
curl -fsS https://v3.elepcloud.com/healthz
```

发布前应按当前主线计划执行 smoke。纯文档变更不需要重启服务；代码、前端或 worker 变更才需要 build 和 restart。

## 15. 常见问题

### 15.1 文档解析成功但回答不上

可能原因：

- 文档生命周期已成功，但可检索证据不足。
- 用户问题使用了同义词，首轮检索没命中。
- 目录命中后没有跳到对应章节。
- 会话没有正确继承首次传入的文档范围。

处理原则：

- 先扩大供料和二次检索。
- 对流程类问题补充同义词，例如“处置、应急、报告、通知家属、记录、转院”等。
- 必要时提示用户补充具体文档或场景。
- 不应直接返回固定系统兜底。

### 15.2 静态页任务没有返回链接

可能原因：

- 任务仍在排队或生成中。
- 中间产物已生成，但 publish 状态未回写。
- 第三方页面只拿到首个响应，没有继续轮询或接收回推。
- 产物生成失败，但没有把失败原因转成可读进度。

处理原则：

- 返回 `status_url`、`poll_after_seconds` 或最终链接。
- 已完成后主动补发结果。
- 链接只应出现一次，避免重复刷屏。
- 如果数据不足，先按已有数据生成可解释版本，不应直接失败。

### 15.3 数据库数据很多但回答很慢

可能原因：

- 数据库供料占满上下文。
- 没有先做字段画像、聚合摘要和问题意图判断。
- 没有区分“查明细”“算指标”“做报表”“解释字段”。

处理原则：

- 先用数据源摘要、字段画像和聚合结果供料。
- 明细只在用户明确要求时拉取。
- 报表任务走异步，不阻塞普通问答。
- 不通过降低回答质量来换速度。

### 15.4 第三方图片识别结果重复

可能原因：

- `message_external_id` 或 `idempotency_key` 没有随图片变化。
- 附件 URL 没变但实际内容变了，缓存仍命中旧图。
- 第三方传参没有明确 `message_type: "image"` 或附件字段。

处理原则：

- 每张新图使用新的 `message_external_id` 和 `idempotency_key`。
- `attachment_refs` 传新图片 URL 或对象数组。
- 需要结构化入库时使用 `output_format: "json"`。

### 15.5 第三方希望移动文档分组

使用文档移动接口按 `document_external_id` 修改目标 `dataset_external_id`。该动作只改归属，不重新解析。

### 15.6 复杂任务什么时候转给 Codex 执行器

优先转派：

- 需要生成或修改静态页、报表、PPT、CSV、Markdown 等产物。
- 需要跨多个文件、数据库、模板和页面完成多步骤任务。
- 需要浏览器、脚本、Office、截图校验或本地文件处理。
- 需要客户本地行业版 Codex 读取本地资料。

不优先转派：

- 普通问答。
- 检索证据足够的快速回答。
- 权限范围不明确的任务。
- 需要用户确认但尚未确认的写入、删除、覆盖或发布动作。

## 16. 当前边界

仍需持续优化的方向：

- 文档解析质量：段落语义分段、标题层级、表格结构、实体和名词分词。
- 问答质量：二次检索、目录跳转、流程类问题扩供料、不能回答时的追问策略。
- 数据库理解：字段画像、指标口径、维度聚合、权限视角和可视化模板。
- 异步体验：流式进度、任务断线续传、主动补发结果、失败阶段可读化。
- 性能：并发、模型池、队列观测、静态页任务复用和缓存。
- 产物治理：同数据集稳定复用、修改历史、角色化链接和客户认可版本保留。
- 分布式执行：中转站任务模型、Mac mini 节点代理、行业版 Codex 客户端、空闲算力回流、节点观测和租户配额。

## 17. 企业客户版表达建议

对企业客户沟通时，应重点表达：

- DataMax V3 是企业规模化使用世界顶尖智能体 Codex 的最佳实践方案。
- V3 不是单个聊天窗口，而是企业数据集、权限、任务、执行器、产物和审计的一体化平台。
- 企业可通过 V3 数据中心统一管理文档、数据库、模板、会话和产物。
- 企业可通过分布式 Codex 执行器阵列承接复杂任务、并发任务和长期任务。
- 企业可通过行业版 Codex 客户端在本地无障碍使用智能体能力，并直联自己的 V3 数据中心。
- 智能体完成的报表、页面、脚本、分析结果会回到企业数据集和产物中心，避免散落在个人电脑。
- 敏感数据、客户本地文件和数据库访问由企业自己的权限体系控制，不把 Codex 节点变成绕过权限的数据出口。

对外发布时应删除或弱化：

- 8 服务器服务名。
- 执行器调度、模型路由、节点回流和云端兜底细节。
- 管理密钥、观测密钥和运维命令。
- 内部 smoke、worker、队列实现细节。
- Mac mini 阵列内部调度、节点抢占、执行凭证和资源配额策略。
- 任何供应商、密钥、数据库连接和内部路径信息。

对外版本建议只保留：

- 企业为什么需要这套方案。
- 系统能做什么。
- 主站怎么用。
- 第三方怎么传文档、会话、数据集、业务库和输出格式。
- 报表/静态页如何生成、修改和获取链接。
- 行业版 Codex 如何连接客户 V3 数据中心、本地执行并同步产物。
- 权限隔离和数据安全原则。
